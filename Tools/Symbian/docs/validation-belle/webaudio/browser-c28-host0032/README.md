This is an experimental WebAudio-enabled local build, not an installed CI SIS or a physical-phone test. The policy at commit time is defined by `OptionsSymbian.cmake` and the current Handoff; this frozen C28 run does not establish the current default.

## Evidence and limits

`public/state.json` contains all 15 original browser reports. The strict validator checks suspended-at-zero before the first gesture, exact gain and delay/channel vectors, oscillator and FFT observations, exact PCM16 WAV decoding and rejection paths, then trusted start/suspend/resume/close and clock behavior. Its `native_audio_verified:false` is intentional: browser reports alone do not verify native sound. `public/trusted-input.jsonl` contains the four original real XTest press/release records. The public screenshot `public/native-ready.png` was visually reviewed: the page waits for the real start click, with a 360×532 content viewport. The calibration maps the enabled button center to window-client point (450,223); the input helper adds the window origin (1,25), giving root-screen point (451,248). All actions target the same owned PID/window. `harness/input/` preserves the input sources, not a synthetic DOM click substitute.

`pcm/analysis.json`, `capture.json`, `marks.json` and `ready.json` are unchanged metadata. The raw s16le stereo, 48 kHz capture is external: 15,087,076 bytes, SHA-256 `4943624d59da7983669041fe8b1546e6045c2ab1b29b246551bf63c611292d99`. Both selected running windows have RMS about 3475, dominant frequency 996.566 Hz and about 99.9996% power in the selected band; suspended and closed windows are exact zero. The independent 52-check metadata/raw-identity review is included. It did not recompute spectra or play the audio.

**`timing_alignment_verified:false` remains unchanged.** Host-delivery markers select the analysis windows. Their spread cannot bound an unknown constant queue delay. These observations do not establish exact synchronization, input-to-output latency or seamless pause. Capture extrema describe all chunks; the retained timing anchors are sparse and need not attain those extrema.

`run-summary.json` contains only whitelisted booleans and safe run/status/reference identities from the private outer result. It records host exit zero, no deadline expiry or forced cleanup, owned normal close after functional completion, unchanged pins, and restoration of the guest profile/resources plus configuration/bindings/Qt/devices. The original result, profile, configuration, journal, item lists, inventory and host logs are deliberately absent. The whole acceptance combines these separate gates; neither a browser report nor PCM metadata alone establishes it.

## Prior failures and additional offline cases

`prior-failures/c26/` preserves the original public reports and a sanitized FAIL summary: the newly created context was already running before a trusted gesture. `prior-failures/c27/` preserves the next FAIL: gain passed, but the delay/channel vector returned `[0.25,0,0]` with two mismatches. Both exited zero and restored state, but required forced cleanup and remain FAIL. C28's gesture policy and multi-output cache guard passed the unchanged strict vectors.

`offline-extra/` is a separate successful run (`wa-0a36d4e3c44a48b1b5c0ee8e7c6f3aef`) with three complete public reports. Case A changes merger pull order and checks both full 512-frame channels with a 128-frame delay. Case B checks the full mono Gain(1)→Delay(128) vector. Case C checks lowpass Q = −10log10(2) dB at DC/cutoff/Nyquist (magnitudes 1, √½, 0; phases 0 and −π/2 at the first two points only) and unit allpass magnitude at five frequencies. Nyquist lowpass phase is unconstrained. An independent Python coefficient/vector review is included. This adds offline numeric coverage, not a new PCM PASS, and does not independently identify a particular SDK symbol. Whole-image source/compile/link evidence is separate. Offline wrapper manifest SHA-256 is `a80f0c4e1b9eb9405b3e59d84d517f960e391f044f706d7681655f0ef947f1cb`; wrapper source SHA-256 is `47eec11b3b46c2f40385b12a6105e2dd3eafec3de244c4e9364bb6198eb67c09`.

## Frozen harness and review

`harness/` contains the eight pinned fixture sources, the C28 wrapper and 46-guard preparation record, preservation/input/close helper sources, and four PCM scripts with their preparation checks. `offline-extra/harness/` contains its six pinned fixture sources and wrapper core. Preparation records intentionally retain their historical `PREPARED_NOT_EXECUTED`/pending-build fields; the later frozen runtime evidence above establishes what actually ran. Absolute source paths are historical references, not an instruction to start an emulator. No browser, guest, input or audio producer was executed to create this archive.

Host-only checks can be repeated with `python3 -B verify_public_archive.py`. The archived strict validators can also parse their corresponding stored public state without launching a server. `SHA256SUMS` pins every other file; the SHA-256 of that file is the archive root identity. `copy-provenance.json` binds original public/source files to their exact archived bytes.

This scope does not verify a physical Nokia Belle FP2 device, system audio resource-loss notifications, seamless pause or official EndTask behavior. AudioWorklet remains hidden. MMF MediaElement PCM source creation explicitly rejects with `NotSupportedError`.
