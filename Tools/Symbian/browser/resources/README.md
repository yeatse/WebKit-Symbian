# Browser query resource definitions

`BrowserQuery.rh` contains only the resource layouts needed by `browser_ui.rss`.
The SDK does not supply `avkon.rh`, `eikon.rh` or `badef.rh`. The definitions are
extracted from these official EPL-1.0 sources, with field order, field types and
defaults retained:

- SymbianSource/oss.FCL.sf.mw.classicui commit
  `dcea899751dfa099dcca7a5508cf32eab64afa7a`:
  `classicui_plat/ui_framework_definitions_api/inc/EIKON.RH` and `avkon.rh`.
- SymbianSource/oss.FCL.sf.os.ossrv commit
  `1e9520caca186c601dd9768449b86bc72be39a22`:
  `lowlevellibsandfws/apputils/inc/BADEF.RH`.

`source-hashes.json` records the complete upstream file SHA256 values. The
copyright and EPL notice apply to the extracted definitions. Constants come
directly from the SDK's `avkon.hrh`, `eikon.hrh` and `uikon.hrh`; no firmware
resource IDs are guessed. The SDK host rcomp needs the repository's host-tool
fix for symbolic identifiers with preprocessed input lacking line directives.
Both enum aliases and the named CBA resource link are retained in this source.

The browser owns its resource IDs, generated by rcomp from `NAME WBUI`. Its
resource file is installed next to the browser's application resources and
loaded from the executable's drive. `EDataLayoutAllowEmptyInput` is an official
query layout: `uifw/AvKon/src/AknQueryControl.cpp` in the same classicui commit
sets `iAllowEmptyInput`, which `EditorContentIsValidL()` accepts. This preserves
JavaScript's distinction between an accepted empty prompt and cancellation.
